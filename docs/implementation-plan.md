# AIS3 implementation plan

Each step ends with working software, automated checks where meaningful, a manual review checklist, and an explicit stop for review. Step 1 is approved for commit. Step 2 configuration and database compatibility requirements are being discussed before implementation.

| Step                              | Deliverable                                                                                                                                                          | Review gate                                                                                          |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **1 — Foundation and UI shells**  | Fresh repo; Core/Web/Admin/Console/Tests; HTTPS dev workflow; Razor login variants/register/recovery; React shell, sample users, components; compatibility baseline. | Build and run from README; review layout and component interactions. No live authentication or data. |
| 2 — Persistence and bootstrap     | PostgreSQL/Identity/OpenIddict persistence, schema/migrations strategy, initial administrator CLI.                                                                   | Initialize a fresh database and rerun safely; inspect schema and first administrator.                |
| 3 — Direct account login          | Real sign-in/out, cookie/session policy, admin authorization foundation.                                                                                             | Successful/failed/locked/unconfirmed sign-ins; safe redirects and unauthorized access tests.         |
| 4 — OIDC sign-in                  | Authorization code/refresh/logout flow; validated compact login context.                                                                                             | A test client completes sign-in, token renewal and logout; reject invalid clients/redirects/PKCE.    |
| 5 — Registration and confirmation | Real registration, confirmation links, continuation behavior.                                                                                                        | New/duplicate account cases, valid/expired links, OIDC continuation.                                 |
| 6 — Recovery and profile          | Password reset/change, profile display/edit.                                                                                                                         | Valid/expired/reused recovery links, validation, persisted profile changes.                          |
| 7 — Live administration shell     | Protected React routes/API, session handling, actual overview data.                                                                                                  | Admin/non-admin sessions, expired-session behavior, dashboard counts.                                |
| 8 — User reading and search       | API-backed users, search/pagination/filtering and details.                                                                                                           | Representative dataset, sort/filter/page interactions, access control.                               |
| 9 — User operations               | Account editing, lockout and approved administrative operations.                                                                                                     | Validation, authorization, confirmations and persisted results.                                      |
| 10 — Claims and scopes            | Claim assignment and scope definitions.                                                                                                                              | Authorized CRUD, duplicate/error paths and resulting token claims.                                   |
| 11 — Clients                      | Client settings, redirects, secrets, scopes and PKCE.                                                                                                                | Create/edit representative clients and exercise their OIDC flows.                                    |
| 12 — Mail integration             | RabbitMQ/AliceMailService delivery integration and operational handling.                                                                                             | Message compatibility and delivery/retry/failure behavior.                                           |
| 13 — Staging and hardening        | Configuration, keys, operational logging, deployment and security review.                                                                                            | End-to-end staging flows and deployment/rollback rehearsal.                                          |
| 14 — AIS2 migration               | Rehearsed data migration with validation reports.                                                                                                                    | Compare users/clients/scopes and hashes; test migrated accounts/clients and rollback.                |
| 15 — Production cutover           | Final migration, release checks and operational handoff.                                                                                                             | Approved cutover, smoke tests and recovery plan.                                                     |

Future steps may be refined at their start. Do not implement a later step merely to make the Step 1 sample look functional.
